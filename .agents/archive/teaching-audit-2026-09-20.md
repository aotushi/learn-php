# learn-php 教学文档与练习对应审计

审计日期：2026-09-20。对象是当前工作区，包含已有未提交改动。本文件是维护审计记录，不是新的学习入口。

结论：当前手册可以辅助已有经验的人阅读和运行项目，但还不足以作为连贯的初学者自学课程。主要缺口是学习单元与代码入口的对应、跨文件运行的基础教学、稳定参考与个人实验的边界，以及从跟做到独立编写的过渡。此前合并文档改善了入口和链接，教学顺序仍需重新编排。

本次没有修改手册、练习源码或学习者作业，也没有替学习者实现详情、筛选等独立题。优先级表示教学修订顺序：P1 会明显打断学习；P2 容易造成误解或削弱练习效果；P3 是后续精简。

## 审计依据与范围

完整阅读唯一学习手册 `docs/README.md`（1182 行）、14 个阶段 README；逐项对照 00–04 的 13 个独立参考入口、Pricing 的 5 个类、根测试、ThinkPHP 路由/入口/控制器/验证/认证/异常处理、前端请求与表单，以及被手册引用的检查脚本。Magento 核对定位和示例阅读，不做安装验收。

采用项目已有的 [教学规范](../skills/teach-php-fullstack/SKILL.md) 与 [教程标准](../skills/teach-php-fullstack/references/tutorial-standard.md)：每个学习任务应有明确目标、前置知识、文件、操作、预期结果、独立练习和完成依据。以下区分了可直接核实的错误与教学设计判断。

不把学习者尚未创建的 `my-*.php` 算成缺失文件；手册已明确要求自行创建。详情和筛选也已明确标为待实现，这两项的缺失不是项目故障。

## 主要问题

### F01 · P1 · 只有章节到目录的对应，缺少统一的学习单元到文件的对应

证据：手册第 9–16、32 行；阶段 02 README 第 5–12 行；阶段 04 README 第 5–12 行；阶段 05、08、09 README。

当前并行存在三种编号：手册六章、stages 的 00–13、各目录从 01 重新开始的示例号。手册虽然解释了编号含义，实际学习仍要自行换算：第二章跨 01/02，第三章跨 03/04，第四章去 07/08，第五章回 06，第六章又回 04/05/09。05、08、09 主要指向其他位置，没有各自独立的练习入口。

局部链接很多，也有部分阅读顺序；缺少的是一张覆盖全程、细到小节的对应表。目录 README 的“文件用途”不能回答每一步“现在先读谁、运行谁、改谁、做到哪里停”。

影响：顺着编辑器目录浏览与顺着手册学习会得到不同路线，已经读过和暂时跳过的内容很难辨认。

建议：保留一个学习手册，为每个学习单元确定同一个标识、一个运行入口和一个主要练习产物；正文与源码 README 双向指向同一单元。类文件可组成一个阅读组，不必机械地让一个类对应一章。先确定教学顺序，再决定目录是否需要改名，不先进行大规模搬迁。

### F02 · P1 · 02 阶段没有完整教授“多文件代码怎样运行”

证据：手册第 193–266 行、819–822 行、661 行；阶段 02 README 第 5–12 行；`composer.json` 第 13–17 行；`phpunit.xml` 第 4 行。

2.5 教单文件对象，2.6 转入 PHPUnit。Composer 只介绍依赖安装；namespace/use 在附录只有简短定义。没有带学习者完成“入口加载文件 → 类名与文件位置对应 → 创建另一文件中的对象”的实验，也没有解释测试为什么已经能使用 Pricing 类。

Pricing 被标为可选，但没有可选学习路线。五个类整体出现，没有明确的最小运行入口、阅读顺序、输入输出与修改题。把它标成可选只能说明何时可以跳过，不能帮助已经打开它的人理解。

实测：新 PHP 进程只有 `namespace LearnPhp\\Pricing;`，创建 LineItem 得到 `Class "LearnPhp\\Pricing\\LineItem" not found`；先加载根 `vendor/autoload.php` 后，相同商品的 subtotalMinor() 返回 5000。PHP 官方也明确说明自动加载器需要注册，Composer 的入口需要被加载。[官方自动加载说明](https://www.php.net/manual/en/language.oop5.autoload.php)

建议：在单对象之后补一个小型、多文件运行单元，依次区分 namespace、use、require、Composer 自动加载，再进入测试。Pricing 若保留，明确为“LineItem → 一个计算调用 → DiscountPolicy/PercentageDiscount → OrderTotal/计算器 → 测试”的有序扩展，并解释每次新增的职责。具体类文件无需编号。

### F03 · P1 · 文件读取没有可直接跟做的正常参考基线

证据：手册第 145、163–165 行；`05-files-json.php` 第 7–16 行；`03-functions-exceptions.php` 第 19–25 行。

当前文件读取参考把实际读取注释掉，直接设置 `$json = false`。实跑退出码为 1，输出 Cannot read file，后面的解码与计数不会执行。函数异常参考也保留调试对象输出。手册已经提醒保留这些实验，这是合理的；但没有另给文件读取的正常跟做基线。

对应的独立题 my-json.php 让人解码内存中的文字，没有真正读取文件。因此“文件 → 字符串 → PHP 值”的主题没有闭合。学习者无法先看到一次正常读取，再比较读取失败、JSON 格式错误和结构不符合要求。

另外，参考文件即使恢复读取，json_decode 后就直接 count，没有业务结构判断。用相同两步验证合法 JSON 的 null、字符串、数字，均在 count 时得到 TypeError；这与手册要求追踪“检查结构”仍有距离。[PHP 的 JSON 解码返回值说明](https://www.php.net/manual/en/function.json-decode.php)

建议：保留现有个人实验；提供明确标识的稳定参考或短基线，让正常读取先跑通，再在自己的副本中分别制造三类失败。独立题要包含真实文件读取和明确的结构规则。不要通过覆盖已有实验来制造整洁的参考。

### F04 · P2 · 数组小节存在可核实的内容错误与代码错配

证据：手册第 156 行；`04-arrays-json.php` 第 9–16 行。

手册把 array_filter、array_map、array_values 连续介绍后写“它们接收函数作为参数”。array_values 只接收数组，不接收回调。当前文件也没有 array_map，实际只有 array_filter、array_values 和 json_encode。

实测：ReflectionFunction 显示 array_values 只有一个参数；该参考文件只输出筛选后的 BOOK 商品。[PHP 官方 array_values 参数说明](https://www.php.net/array_values)

影响：读者会寻找文件里不存在的变换步骤，并误以为重排索引也需要回调。

建议：解释严格对应当前代码；若需要教授 array_map，为它增加明确的示例与观察任务。把“筛选”“变换”“重排索引”分开，逐步展示输入数组和结果。

### F05 · P2 · 框架与 HTTP 检查的独立题跨度过大

证据：手册第 397–410、473–482、519–525、703–709 行；`scripts/api-smoke.php` 第 12–46、49–104 行。

4.1 有请求链阅读表，优于纯文件清单，但第一次框架阅读同时进入入口、路由、中间件、控制器、验证和异常处理。随后独立题要求增加受保护的详情，再自行编写带登录、断言、失败退出和清理的 HTTP 检查脚本。

“复用 api-smoke 的辅助方法”缺少边界说明：这个文件包含辅助函数，也在顶层立即执行整套检查；它不是可以安全当作纯工具库直接 require 的文件。当前手册没有演示一次最小 HTTP 断言如何从请求结果产生通过或失败。

这是教学设计判断，不是“独立题必须给完整答案”。已有 JavaScript/Vue 经验会降低难度，但 PHP 中首次出现的 global、cURL 选项、返回数组约定、异常清理仍被集中放进一个任务。

建议：先跟通一个最小框架响应，再加查询、输入验证和权限；复用相同请求进行比较。HTTP 检查先给可单独使用的最小请求工具和一个示范断言，再要求独立增加状态、数据不变和清理检查，不代写业务答案。

### F06 · P2 · 一些练习缺少即时反馈，示例主题与作业产物跳转较多

证据：手册第 114、147、165、169–186、238、266、452 行；语法目录 README 第 14 行。

2.4 指向订单合计参考，实际作业却是价格字段验证；两个任务目标不同，手册虽已说明“不要复制”，仍缺一个中间步骤说明本次怎样复用前面的知识。函数要保存为不打印的文件，到隔着对象小节的 2.6 才给出测试入口。

2.4 又规定部分规则到第四章补齐，2.6 则要求增加上限和邻界测试；当前阶段的完成边界没有单独列清。2.6 的“上节自己实现的函数”实际指 2.4，不是紧邻的 2.5。数量函数和第四章状态函数也没有统一标明文件、调用入口与完成检查。

影响：学习者可能写完函数没有输出，又不确定是完成了还是没有运行；跨章回来时难以辨认哪部分仍待完成。

建议：每个独立题就地给最小调用或检查命令，把本节必做与后续扩展拆清。同一个示例尽量沿一个业务目标推进；切换目标时明确说出复用哪一步、舍弃哪一步。

### F07 · P2 · 选读内容仍混在主线默认验证中

证据：手册第 18、229–235、410、519–525、661 行；`phpunit.xml` 第 8–9 行；根 tests 两个文件；`scripts/api-smoke.php` 第 77–81 行。

Pricing 被归为可选，第二章默认 composer test 却会运行 Pricing 的测试和阶段 07 ProductInput 的测试。商品网址被列为以后再读，主线必跑的 API 检查仍测试网址新增、协议验证、归属和删除。

这些检查本身有价值，也不等于要求学习者读懂全部代码。问题在于手册没有把“当前单元要理解的证据”和“整套项目回归检查”在执行入口和结果解释上讲清楚。学习者遇到尚未学过的测试失败时，无法判断是否需要停下主线去补课。

建议：按当前单元提供有限的学习检查；保留维护者完整回归。对完整回归只解释其作用和失败时的处理边界，不用所有绿灯充当当前单元的理解证据。

### F08 · P3 · 单页内仍有多余查阅负担，部分观察任务需要分层说明

证据：手册第 575、937–1007、1019 行；`ProductForm.vue` 第 23–26 行。

Linux 网络/资源命令、JWT 等当前主线未使用的查阅项仍占用大量篇幅。附录已折叠并标为按需，问题比原先散落多份文件轻，但仍可按实际练习使用情况精简。首次必需的环境准备放在千行后的附录，正文只跳转；可在总览就明确区分“首次准备一次”和“从当前学习单元继续”。

5.2 要求在页面尝试空名称、负价格和重复 SKU。源码里前两项有浏览器 required/min 约束，重复 SKU 才会到服务端检查。手册未说明这些提示可能来自不同层。这个观察项可以保留，但应要求先判断请求是否实际发出，再分别验证服务端拒绝，避免把浏览器拦截当成服务端证据。本项是源码审查结论，未完成浏览器点击复测。

建议：正文只保留当前必需知识；每次失败观察明确“浏览器拦截、请求到达 PHP 后拒绝、数据库拒绝”分别用什么证据判断。

## 实际验证及其边界

- 文档链接检查：21 份 Markdown、139 个本地链接通过，锚点有效。
- 手册与根 README 的命令注释检查通过；它只检查命令前有无说明。
- 00/01/02 的 8 个参考 CLI 入口实跑：7 个正常退出；05-files-json.php 按当前故障实验退出 1。03-functions-exceptions.php 输出异常对象调试信息。
- 阶段 04 的 3 个参考实跑：查询正常；执行计划命中 SKU 索引；事务例子输出 Updated rows: 1、Remaining test rows: 0。临时商品被回滚，自增序号可能正常消耗。
- HTTP 实测：HTML 特殊字符转义正常；原生商品门槛 5000 返回 200 和数据，-1 返回 422；框架健康接口 200；无令牌商品列表 401。
- PHPUnit：7 项测试、24 条断言通过，使用不写测试缓存的选项。
- 单独复现了 namespace 不加载类，以及加载 Composer 后可创建对象；验证了 array_values 的参数数量与 JSON 标量直接 count 的结果。
- 浏览器自动化连接未完成，没有把表单点击、登录后的完整 CRUD 或所有独立作业列为本次已实测。第五章表单约束结论来自实际组件源码。
- 未重新安装依赖、重置数据库或启动 Magento。没有修改现有教学文件、个人练习和业务实现。

这些结果支持“项目的一部分能正常运行”，也具体证明有教学错配。测试通过不能推导出新读者能够按手册独立学会。

## 建议的修订顺序与验收

1. 先建立覆盖每个主线学习单元的“目标—参考文件—运行入口—自己的练习—预期结果”表；正文与目录索引使用同一标识。
2. 优先修 01/02：稳定正常参考、数组事实错误、文件读取闭环、namespace/use/require/自动加载的动手实验。
3. 再拆解 03/07 的过渡：先最小请求/响应与查询，再验证和权限，最后独立详情；提供可独立使用的 HTTP 检查工具。
4. 整理当前单元检查与全项目回归的边界，补齐所有独立题就地运行和反馈。
5. 最后精简附录、旧 Day 标记和只做跳转的目录；保持一个学习手册，不再新增第二套路线。

修订完成应由一个不借助历史聊天的阅读过程验证：每一步能从手册找到确切文件和入口，观察已声明的正常/失败结果，完成一个相邻难度的独立变化，然后知道下一步。接口、类文件和附录允许按职责组织，但不能要求学习者自行拼接这条路径。
