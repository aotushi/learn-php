# 学会 PHP 8 后能否使用 PHP 7

## 简短结论

可以维护多数 PHP 7 代码，但不能假设 PHP 8 代码可以原样运行在 PHP 7。

PHP 的变量、数组、函数、类、接口、异常、命名空间、Composer、HTTP 和 PDO 等核心知识高度相通。真正需要补的是“目标 PHP 7 小版本缺少哪些语法和函数，以及旧项目依赖什么旧框架”。

PHP 7 全系列已经停止官方支持，不适合新项目。新学习项目继续使用仍受支持的 PHP 8.4；只有接手遗留系统时，才在隔离的 Docker 环境中运行相应 PHP 7 版本。

## PHP 8 代码回到 PHP 7 时的常见障碍

| PHP 8 写法或行为 | PHP 7 中的处理 |
| --- | --- |
| 命名参数 | 改为按位置传参 |
| Attribute 属性标注 | 删除或改用注释、配置文件 |
| 构造器属性提升 | 单独声明属性并在构造函数赋值 |
| 联合类型 | 删除联合类型或改用文档注释和运行时检查 |
| `match` 表达式 | 改为 `switch` 或条件分支 |
| 空安全运算符 `?->` | 先判断对象是否为 `null` |
| PHP 8.1 枚举 | 改为常量或值对象 |
| `readonly` 属性或类 | 通过私有属性和无修改方法约束 |
| `str_contains()` 等新函数 | 使用兼容函数或旧写法 |
| 更严格的类型和错误行为 | 重新测试比较、内置函数参数和错误处理 |

PHP 8 还删除了一些 PHP 7 中已经弃用的旧能力，并调整了字符串与数字比较、错误类型和 PDO 默认错误方式。因此，“会 PHP 8”足以读懂大多数 PHP 7 项目，但开始修改前必须运行该版本的测试并阅读对应迁移指南。

## 对 ThinkPHP 的影响

ThinkPHP 8.1 要求 PHP 8.0 以上，不能安装到 PHP 7。如果工作要求维护 PHP 7 + 老 ThinkPHP，应当：

1. 先确认准确的 PHP 和 ThinkPHP 小版本。
2. 用单独 Docker Compose 文件隔离旧运行环境。
3. 先运行现有测试和依赖检查，不要直接降级当前项目。
4. 只补目标项目实际使用的兼容知识，不重新学习全部 PHP 7 历史。

## 建议顺序

先用 PHP 8.4 建立正确的类型、安全、测试和工程习惯。以后遇到 PHP 7 项目，再安排 2–5 天做迁移差异训练，通常比一开始围绕已经停止支持的版本学习更有效。
