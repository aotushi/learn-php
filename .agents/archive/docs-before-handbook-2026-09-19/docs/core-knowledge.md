# 先学透五个核心问题

这不是新增一门课，而是原来 30 天教程的优先级说明。目标不是把章节看完，而是获得能换场景使用的后端能力。每天仍从 [学习路线](learning-path.md) 进入，只在卡住时回来查本页。

## 哪些内容值得反复花时间

| 核心问题 | 在本项目里具体理解什么 | 什么时候重练 |
| --- | --- | --- |
| 1. PHP 怎样处理一次请求？ | 容器、程序、请求不是同一件事；本次请求的普通变量不等于数据库中的持久数据 | 第 1、8、12、19、28 天 |
| 2. 不可信输入怎样变成可靠输出？ | 数组、类型、函数、验证、异常、JSON 响应形成一条处理链，而不是各背一个定义 | 第 4–7、12、14、16、29 天 |
| 3. 数据怎样保持正确？ | 参数绑定区分代码和数据；约束兜住非法状态；多个写入由事务保证一起成功或回滚 | 第 11–12、15、26、29 天 |
| 4. 谁能做什么，在哪里检查？ | 登录识别身份，权限决定操作；检查必须在服务端，不能依赖隐藏按钮 | 第 17、21–22、29 天 |
| 5. 怎样用证据判断程序对不对？ | 先预测，再看输入/响应/数据库；最小复现、边界测试、故障定位比反复重装有用 | 第 5、10、18、24–30 天 |

这些模型在原生 PHP、ThinkPHP 和后续 Magento 中都会用到。框架的方法名可以查，但不能把“数据库为什么不该写入这条数据”的判断交给记忆中的方法名。

## 三种学习深度

- **必须独立掌握**：上面的五个核心问题，以及完成练习需要的基础语法。能解释、自己实现一个小变式，并定位失败。
- **能使用、能查资料即可**：Docker 命令参数、Composer 选项、框架目录和方法名、SQL 语法细节。命令注释继续保留，不考缩写拼写或背手册。
- **暂时不展开**：复杂对象设计、readonly 的深入语义、缓存、队列、完整订单/库存系统、前端架构重建。Magento 第二阶段再进入。

这不是删掉验证、权限等“麻烦内容”，也不是只教复制代码。它们恰恰是核心；暂缓的是当前任务不需要的广度。

## 一次练习，留下四种证据

1. **解释**：关掉答案，用自己的话说明为什么这样做，不只复述代码。
2. **独立实现**：可以查函数签名和命令词典，但不复制参考业务实现，也不让 AI 直接代写。卡住时先说出假设，再索取一个提示。
3. **定位失败**：自己设计一个正常、一个边界、一个错误输入，预测后运行；说清错误发生在哪一层。
4. **隔天迁移**：换字段、换边界或换实体，再做一次同类小题，不重读整份答案。

同一题能独立做对后，不需要无止境重复。是否继续深入，由新变式能否完成决定，而不是“这一天安排了多少新名词”。

自动测试通过只证明被覆盖的程序行为符合预期，不能证明学习者已经掌握。见 [独立练习关卡](practice-checkpoints.md)，记录方式见 [进度清单](progress-checklist.md)。

## 怎样用满一天，而不是赶完一天

6 小时只是可用时间，不是每个主题必须占满同样长度。可参考：半小时不看资料复述、半小时补必要知识、1 小时跟做、2 小时独立变式、1.5 小时验证排错、半小时记录。

已经熟悉 Vue 的部分，验证请求链路后即可，把时间还给 PHP、数据库和权限。核心关卡没过，可以挪用后面的巩固时间；不要为了第 30 天打完所有勾而跳过它。删减边缘内容，不删减理解与反馈。
