# 五个独立练习关卡

这些练习替换当天的部分跟做时间，不额外增加课程量。按日期做对应一节即可。先尝试，再展开提示；允许查语法，不复制参考业务实现。练习文件自行新建在对应 stages 目录，保留原参考文件；数据库写入只操作自己新建的练习商品。

通过标准统一为 [解释、独立实现、定位失败、隔天迁移](core-knowledge.md)。先记“跟做过”，独立题通过后才记“独立完成”。

<a id="checkpoint-request"></a>

## 1. 请求与状态（第 8、12 天；第 19 天复述）

**先预测**：一个 PHP 文件每次把普通变量从 0 加到 1，刷新三次会显示什么？容器一直运行，是否意味着这个变量一直累加？

**自己实现**：在 stages/03-web-security/public 新建 my-request.php，只做“接收 name、没有就使用默认名、返回 JSON”。可参考 PHP 函数用法，不复制现成控制器。默认 Web 地址下访问 /my-request.php；记录发了什么、PHP 读到什么、回了什么。

**验收**：缺少 name 有默认值；name=Lin 返回 Lin；name[]=Lin 是数组输入，应返回 422 和可读错误，而不是数组转字符串警告。普通变量每次初始化，数据库商品仍能跨请求读到。解释请求结束与服务器进程退出为什么不是一回事；这里只讨论当前传统 PHP Web 示例，不推广到所有常驻 PHP 框架。

<details>
<summary>卡住再看提示</summary>

沿“URL 查询参数 → 类型检查 → 默认值/拒绝 → JSON → 状态码”拆解。PHP 的普通请求变量与 MySQL 行的生命周期不同；不必先实现 Session。响应头应声明 JSON，不能用 echo 数组代替编码。

</details>

**隔天变式**：将 name 换成 quantity，允许 1–10 的整数；为空、0、11、数组分别怎么办？先写规则，再写判断。

<a id="checkpoint-input"></a>

## 2. 输入到输出（第 7、14、16 天；第 29 天迁移）

**先预测**：0、"0"、null、缺少字段、[]，是不是同一个输入？声明 strict_types 是否会替你判断商品价格合法？

**自己实现**：在自己的练习文件写 readPriceMinor(array $input): int。契约：price_minor 必须存在，是 PHP 整数或只包含十进制数字的字符串，范围 0–100000000；字符串 "00" 也接受为 0；负数、浮点、布尔、空字符串、空格、数组、null、缺失均抛 InvalidArgumentException。这是独立题的规则，不要求照抄参考 ProductInput 的每个行为。

**验收**：为 0、"9900"、100000000、100000001、-1、1.5、true、"9.9"、" 9 "、[]、null 和缺失分别写出预测与断言。第 7 天先做整数/负数/缺失，第 14 天补齐类型，第 16 天不看答案重写一个状态字段验证器。

<details>
<summary>卡住再看提示</summary>

先区分字段不存在和类型不合法，再检查范围；不能先强制转 int，否则 true、"9.9" 等可能被悄悄改变。最后才返回规范化后的整数。第 7 天不需要一次写完所有边界。

</details>

**迁移**：把同样的“存在性 → 类型 → 值范围”思路用于第 29 天的查询参数，而不是复制价格函数去验证所有字段。

<a id="checkpoint-data"></a>

## 3. 数据正确性（第 11–12、15、26 天）

**第 11–12 天自己写查询**：在 stages/04-data-storage/exercises 新建 my-query.php。可以复用连接语句，SQL 自己写：只返回 status=enabled 且 price_minor>=5000 的商品，字段为 sku/name/price_minor，按 price_minor、id 升序。两个条件都用参数绑定，不拼接外部输入。

**验收**：对照你当前数据库逐行确认结果，不把固定种子数量当答案。把门槛改为 5000 两侧，用自己创建的商品验证“包含等于门槛”。解释如果没有匹配项，空列表为何不是服务故障。第 15 天以重复 SKU 请求说明：前端验证、PHP 检查、数据库唯一约束各能保护什么，为什么不能只保留前端检查。

**第 26 天自己写事务**：只新建两件随机 SKU 的临时商品，在第二次写入前主动抛异常，捕获后回滚；再用相同结构在第二次写入后抛异常。先预测每次回滚后有几行，再 SELECT 核对，预期均为 0。不修改/删除现有商品，不移除回滚逻辑，不做真实订单系统。

<details>
<summary>卡住再看提示</summary>

SQL 占位符绑定的是值，不是表名或列名。事务范围从 beginTransaction 开始；抛异常本身不等于你已正确执行 rollBack。把开始、两个写入、异常、回滚和最终查询逐个标在纸上；随机 SKU 用来准确识别你自己的测试行。

</details>

**迁移**：不用执行，解释若两个相关写入分别在两个连接上进行，一次连接上的回滚为何不自动撤销另一个连接的提交。

<a id="checkpoint-auth"></a>

## 4. 身份与权限（第 17、21–22 天）

**先预测**：不带令牌、viewer 令牌、admin 令牌，分别请求商品列表和修改商品，会发生什么？先写一个三行两列的预期表，再按 [手动接口练习](api-workshop.md) 发请求，不依赖页面按钮。

**自己验证**：只修改自己新建的商品。请求前后读回其价格，证明 viewer 的写请求不仅返回 403，而且确实没有写入；admin 能修改。服务端退出后旧令牌返回 401。完整页刷新只会丢失示例前端的内存令牌，不等于服务端已经撤销它。

**验收**：无令牌 401；viewer 读成功、写 403；admin 读写成功。可以直接用 PowerShell 绕过页面，但不能绕过后端权限。说明认证（是谁）与授权（能做什么）的差别。

<details>
<summary>卡住再看提示</summary>

沿 Authorization 请求头 → 令牌检查 → 用户角色 → 写操作检查寻找证据。客户端声称自己是 admin 不能替代服务器查到的角色。仅看到隐藏按钮，不能填“独立完成”。

</details>

**隔天变式**：令牌过期但按钮仍显示时，哪一层应拒绝？用文字描述，不必等一小时，也不改动别人会话。

<a id="checkpoint-debug"></a>

## 5. 证据与排错（第 10、18、24–25 天）

**先建立自己的检查**：第 10 天临时改错断言只用于理解工具；随后必须独立写一个“零数量应被拒绝”的小测试。第 18 天独立补一个 viewer 修改商品的检查，不只重新运行 api-smoke.php。

**一次可恢复故障**：在自己新增的价格验证函数里，临时把最大值判断从“允许等于上限”改成“不允许等于上限”。先预测哪一个测试会失败，运行、读报错、只修这一处、重跑。不要故意关闭权限检查或更改共享数据库账户。

**验收**：留下五行：输入、预期、实际、定位证据、修复后结果；能解释为何普通价格通过但上限用例失败。若独立测试写不出来，回到输入关卡，不把 59 项参考检查通过当作学习证据。

<details>
<summary>卡住再看提示</summary>

先缩小到一个函数和一个输入，再查堆栈、规则与比较符。不要同时修改测试预期和业务实现，否则可能把错误“改成通过”。原生 PHP 单独文件的错误看本次终端，HTTP 错误再沿浏览器、应用、数据库查证据。

</details>

**隔天迁移**：在其他规则上选一个相邻边界，例如数量 1/0，再写一组测试；不是复述昨天的数字。
